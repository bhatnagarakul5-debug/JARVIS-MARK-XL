## 1. Core Philosophy: Absolute Data Sovereignty

J.A.R.V.I.S. is engineered on the principle of **Local-First Sovereign Intelligence**. Unlike commercial cloud-based virtual assistants that harvest telemetry, monetize behavioral profiles, or transmit continuous ambient background audio, J.A.R.V.I.S. operates as a dedicated, private executive co-pilot anchored to the user's personal hardware.

- **Zero Third-Party Telemetry:** J.A.R.V.I.S. transmits no analytics, behavioral telemetry, or diagnostic tracking to advertisement brokers, data aggregators, or unauthorized third parties.
- **Local Storage by Default:** Conversation logs, memory graphs, student attendance records, timetables, face biometric embeddings, and generated files reside exclusively on the host workstation.
- **Air-Gapped Privacy Controls:** All camera, audio, and file execution routines are strictly gated by explicit user invocation.

## 2. Information Handled & Processing Architecture

### A. Voice & Audio Telemetry
- **Microphone Stream:** Audio input is captured via local audio devices (e.g. Realtek, Bluetooth) for real-time speech-to-text inference.
- **Streaming Pipeline:** Audio frames sent to Google Gemini Live API are transmitted over TLS-encrypted WebSockets solely for conversational response synthesis.
- **Ambient Silence:** When inactive or muted, microphone processing is paused. No persistent background audio recordings are retained on external servers.

### B. College & Academic Data (STUNT Platform & College Hub)
- **Coursework & Timetable:** NMIMS Mumbai BBA IB academic data, attendance records, CGPA calculations, and syllabus files are queried directly from the local SQLite database (`stunt_database.db`).
- **Outlook College Communications:** Synchronized notices, emails, and lecture slides are parsed on-device. No institutional credentials or college emails are synchronized with third-party servers.

### C. Visual Media & Biometrics
- **Webcam Security Feed:** The camera system is activated only upon explicit voice command (`camera_control`, `security_footage`) or automated sentry mode on workstation lock.
- **Face Recognition Profiles:** Facial landmark features are stored locally in `config/known_faces` as encrypted NumPy arrays. No facial imagery is uploaded to external public biometric registries.

### D. File Generation & Executive Documents
- **Output Storage:** Presentations (`.pptx`), Word documents (`.docx`), PDFs, and spreadsheets (`.xlsx`) generated by J.A.R.V.I.S. are written directly to local user directories (`Desktop`, `Downloads`, `Documents`).
- **No External Replication:** Generated documents are never duplicated to unapproved cloud repositories.

## 4. Endpoint & Server Security Safeguards

To prevent external interception or unauthorized remote control, J.A.R.V.I.S. implements multi-layered defensive security features:

1. **Localhost Isolation:** All internal IPC and local server endpoints are strictly bound to `127.0.0.1` and `::1`, preventing discovery or exploitation across shared local networks or public Wi-Fi.
2. **Telegram Whitelist Guard:** Remote command execution is restricted to verified, pre-approved Telegram Chat IDs. Unauthorized callers are blocked and logged.
3. **Sandbox & Path Traversal Shield:** Remote file access commands (`/get`) enforce canonical path validation, barring access to Windows system root directories, SSH keys, `.env` files, or credential vaults (`config/api_keys.json`).
4. **Token Bucket Rate Limiting:** High-frequency incoming requests are throttled to mitigate brute-force and denial-of-service attempts.
5. **Security Event Audit Logging:** Tamper-evident event records are maintained locally in `memory/security_events.log`.

## 5. User Sovereignty & Data Erasure

The user retains complete administrative sovereignty over all information stored by J.A.R.V.I.S.:

- **Memory Erasure:** Conversation logs (`memory/conversation_log.json`) and semantic memories (`memory/user_memory.json`) can be modified, audited, or wiped at any time via voice command (`"wipe conversation memory"`) or direct file deletion.
- **Credential Storage:** All API keys are isolated in `config/api_keys.json`, which is permanently shielded from Git commits via `.gitignore` and verified by `security_audit.py`.
- **System Decommissioning:** Deleting the project folder permanently removes all local databases, face profiles, and memory logs from the host computer with zero lingering cloud remnants.
